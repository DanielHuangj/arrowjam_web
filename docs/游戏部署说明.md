# Arrow Jam 游戏 — 服务器部署说明

游戏为**纯前端静态站点**（Vite + Canvas），运行时通过 `fetch` 加载 `/levels/*.json`。服务器上**不需要** Node 进程、数据库或 API，只需 Nginx（或同类 Web 服务器）托管构建产物。

关卡编辑器（`code/editor/`）与游戏独立，本文仅说明**游戏客户端**部署。

---

## 1. 本地构建

在开发机安装 Node.js 18+，执行：

```bash
cd code/client
npm install
npm run build
```

构建前 `prebuild` 会执行 `import-levels`：若 `code/client/levels-inbox/` 有待导入 JSON 则写入 `public/levels/` 并更新 manifest；inbox 为空时仅刷新 manifest 中的 kinds 字段。

产物目录：**`code/client/dist/`**，结构示例：

```
dist/
├── index.html
├── assets/          # 带哈希的 JS/CSS
├── levels/          # manifest.json + level-*.json
├── icons.svg
└── favicon.svg
```

本地可先验证：

```bash
npm run preview
# 浏览器打开 http://127.0.0.1:5173/
```

---

## 2. 上传到服务器

将 **`dist/` 目录内的全部文件** 放到服务器站点根目录，例如 `/var/www/arrowjam/`。

注意：上传的是 `dist/*` 的内容，不要在站点根下再套一层 `dist` 文件夹，否则 `assets/` 会 404。

任选一种方式：

```bash
# scp
scp -r dist/* user@your-server:/var/www/arrowjam/

# rsync（推荐，便于增量更新）
rsync -avz --delete dist/ user@your-server:/var/www/arrowjam/
```

确保 Nginx 运行用户可读该目录（Debian/Ubuntu 常见为 `www-data`）：

```bash
sudo chown -R www-data:www-data /var/www/arrowjam
```

---

## 3. Nginx 配置

在已有 Nginx 上新增一个 `server` 块，或合并进现有站点配置。将 `server_name`、`root` 换成你的域名或 IP、实际路径：

```nginx
server {
    listen 80;
    server_name your-domain.com;   # 或服务器 IP

    root /var/www/arrowjam;
    index index.html;

    location /levels/ {
        try_files $uri =404;
        add_header Cache-Control "public, max-age=3600";
    }

    location /assets/ {
        add_header Cache-Control "public, max-age=31536000, immutable";
    }

    location / {
        try_files $uri $uri/ /index.html;
    }

    gzip on;
    gzip_types text/css application/javascript application/json;
}
```

检查并重载：

```bash
sudo nginx -t
sudo systemctl reload nginx
```

若使用防火墙，放行 80（及 443）：

```bash
sudo ufw allow 80
sudo ufw allow 443
```

仓库内有一份相同示例：`deploy/nginx/arrowjam.conf`（仅供参考，不必使用 `deploy/` 下的脚本）。

---

## 4. HTTPS（可选，有域名时推荐）

域名已解析到服务器后：

```bash
sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d your-domain.com
```

按提示完成即可；Certbot 会自动修改 Nginx 并配置证书续期。

## 5. 验收清单

浏览器访问 `http://your-domain.com/` 或 `http://服务器IP/`，确认：

- [ ] 首页可打开，关卡列表正常加载
- [ ] 开发者工具 Network 中 `GET /levels/manifest.json` 返回 200
- [ ] 任选 L29、L30、L61 可进入并游玩
- [ ] 无 404（尤其 `/levels/level-*.json`、`/assets/*`）

命令行快速检查（将 `BASE` 换成你的地址）：

```bash
curl -I http://BASE/levels/manifest.json
curl -I http://BASE/levels/level-29.json
```

## 6. 更新与常见问题

### 日常更新（推荐）

开发完成后，在仓库根目录执行：

```powershell
# 首次：复制 deploy/env.example 为 deploy/deploy.env，填写服务器 SSH 地址
.\deploy\update.ps1
```

脚本会依次：**本地 `npm run build`** → **rsync/scp 上传 `dist/` 到服务器** → **远程 smoke test**。

服务器应用目录默认为 `/data/yunwei/arrawjam`，可在 `deploy/deploy.env` 中修改 `DEPLOY_PATH`。

验收地址通过 `SITE_URL` 配置（例如 `http://arrowjam.farfieldgames.com:18080`）。上传用户即为运行账户，脚本**不会**执行 `sudo chown`。

```powershell
.\deploy\update.ps1 -SkipBuild       # 仅上传，不重新构建
.\deploy\update.ps1 -SkipSmokeTest   # 上传后不做 HTTP 验收
```

### 只更新关卡

在 `code/client/levels-inbox/levels` 或 `devTests` 放入 JSON 后执行 `npm run import-levels`，或重新 `npm run build`，再同步服务器上的 `levels/`（或整个 `dist/`）。详见 `code/client/levels-inbox/README.md`。

### 关卡列表空白 / 加载失败

- 确认服务器上存在 `/var/www/arrowjam/levels/manifest.json`
- 确认 Nginx `root` 指向正确目录

### 页面白屏

- 多为 `assets/` 404：检查是否误把整个 `dist` 文件夹上传成子目录
- 在 Network 面板查看哪个 JS/CSS 请求失败

### 在子路径部署（如 `/games/arrowjam/`）

需在 `code/client/vite.config.ts` 设置 `base: '/games/arrowjam/'` 后重新 `npm run build`，Nginx 的 `location` 也需对应调整。默认按**站点根路径**部署。

### 不建议在服务器上 build

请在本地构建并执行关卡导入，只上传 `dist/`。

---

## 7. 架构示意

```
浏览器  --GET /-->              Nginx  -->  dist/index.html + assets/
浏览器  --GET /levels/*.json-->  Nginx  -->  dist/levels/
```

无后端、无 WebSocket；编辑器不在此部署流程内。
